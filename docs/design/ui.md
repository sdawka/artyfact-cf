## C.1 Shell
TopBar: Wordmark (Georgia, links to Home), SystemRevisionSelector (+ state pill canonical | candidate | deployed, options from `GET …/revisions`), PhaseBadge, ⌘K CommandPalette (cmdk over byId). The layer switch (label "Overlay") lives in the Map header. SideNav: Map first and Overview second at the top level, then one group per layer, Private Parts last. Each group is headed by the layer name (its accessible label) with the layer's question beneath in quiet sentence case (its accessible description): Genome, "What should it be" (Journeys, Theory, Code); Proteome, "What is being made" (Work, Review, Evaluations, Changelog); Phenome, "What does it do" (Deployments). The Overview meters carry the same three questions (`LAYER_QUESTIONS` in `model/kinds.ts`). Review shows a count after its label when decisions wait (attention tone, hidden at zero, link named "Review, n waiting"). Compare is not on the rail; it opens from a Changelog row's "Compare with parent" and `g x`. Inside a Thing workspace the rail links resolve to `/things/:thingId/<view>`; there is no separate Thing workspace link. Under 640px the rail collapses to glyphs and keeps the three layer heads visible. Go-to keys: `g o m j t c w r e l x d` (`g h` still opens the Changelog). Main Outlet. InspectorDrawer right 380px resizable; other views open it when focus is set, while Map requires explicit Details (`inspect=1`); Esc closes; `[`/`]` siblings; `g m`/`g w` shortcuts. Grid `auto 1fr auto`.

## C.2 Map
**Implemented System atlas; local CI passed. Hosted checks are tracked on [PR #66](https://github.com/sdawka/artyfact-cf/pull/66).** Map is the primary System entry, followed by the existing specialized views. React Flow provides the viewport; deterministic `atlasLayout` packing replaces Map ELK placement. Environment shows the System and all declared externals, including disconnected actors, without invented roles. Entered scopes show their immediate real containment children and direct one-hop outside context; template view hints never skip containment. Outside scope and outside System remain distinct.

Tiles form a rectangular mosaic without gutters, using thin shared dividers and content-based S/M/L budgets for name, kind, short purpose and bounded child previews. Geometry is independent of selection, relationship visibility, Details and layer overlays. Genome, Proteome and Phenome remain parallel overlays on that same layout; existing evidence and candidate signals retain their meanings.

Click selects and reveals boundary-crossing relationships; Details explicitly opens the Inspector. Enter or double-click opens only nonempty containers; leaves remain inspectable. Grouped lines retain every normalized original endpoint, relationship, label, certainty and count, with actual endpoint paths and Locate actions exposed in the relationship list/Inspector. Offscreen selected endpoints have indicators. Tree and filters are on demand; mobile uses compact context and a bottom Inspector.

Map URLs use `scope=environment|containerId`, `focus` for selection, and `inspect=1` for Details. Valid explicit scope wins; legacy focus and Thing routes remain supported. Scope changes push browser history; selection and Details replace it. Selecting closes Details without changing scope. Cameras restore per System/revision/scope. Drag, ordinary scroll and touch pan; pinch or modified scroll may enter/leave depth only past a threshold, once per gesture, never entering an empty container or leaving environment. Explicit Up/Enter and keyboard paths remain available; reduced motion makes transitions immediate.

Full local CI, independent review and parent visual inspection support this implementation; PR review and hosted checks are tracked in [GRREAT](../grreat/execution.md). No atlas deployment is claimed.

## C.6 Work
New work follows the [lifecycle](lifecycle.md): Genome-only Evolutions and separate Realization plans pinned to accepted Genome revisions. Work exposes Tasks, scope interference, dependencies, attempts and one combined implementation review. Older Evolution-owned attempts remain readable as legacy history. `/start` previews native ontology packages and preserves invalid conversion output for correction before exact-hash acceptance.

EvolutionBoard columns by state; EvolutionCard scope chips, "≈ overlap" when any of its candidates conflicts and "N await review" (attention) when candidates or amendments wait; RealizationRow (agent, role, local/hosted, status, fork + short sha, last checkpoint or "unknown", changed subjects, ConflictChips typed, inline "Review" toggle, "Open in Review"); StartWorkPanel → PacketViewer (markdown, copy, CLI line, token countdown); inline CandidateReview tabs Semantic delta / Files / Evaluations / Amendment, "select for composition" → `?candidates=`. "Promote in Review" is a link to Review's desk (`/review?evolution=E&panel=promote`, keeping `?candidates=`); `/work?panel=promote` redirects there. The card's "N await review" counts candidates, stale candidates and amendments, not the promotion row.

## C.6a Describe a change by intent
`?panel=intent` on Work (`views/work/intent/`): a message, optionally anchored on a node, becomes a Proposal (routed path, ops with an include toggle each, questions with inline replies). The proposal already links to a durable Genome Evolution. Accept selected commits its reviewed Genome change; implementation starts separately in a Realization plan. While the panel is open it replaces the Evolution board and detail; its head shows the anchor as a node chip with "Clear anchor", and "Back to board" closes it and keeps the other params. "Describe a change" is the one label at every entry (Work header, Home card, Inspector, Code file pane) and the Work header's one primary action; "+ Evolution" is a secondary text button. The UI is driven by template view hints, not by node kind (`docs/design/ontology.md`).

## C.6b Review
`/review` (`views/review/`), the operator's inbox and promotion desk, two panes. Left, the decision queue ("Waiting on you N"), grouped by Evolution, one row per pending decision: `candidate` (submitted/evaluated, not promoted or rejected), `stale` (its base is behind head, dashed attention), `amendment` (Genome realization `awaiting-admin`), `promotion` (an Evolution with an evaluated candidate on the current head). A row shows the kind word, agent and role, candidate id ("selected for composition" when it is in `?candidates=`), ConflictChips (one per kind, with the count) and "base = head" (neutral), "behind by N" or "behind head" when the distance is unknown (attention); a promotion row reads "ready to promote". Within a group: amendments, then candidates, then the promotion row. Right, the selected row: CandidateReview (`?evolution=&realization=`, its Amendment tab carries Accept with interpretation / Reject with reason) or PromotionPanel (`?panel=promote&evolution=`) with the gates summary "4 pass · 1 unknown" (success tone only when every required gate passes) and, on a 409 stale-base, the agent's recovery line: rebase the fork on the new head and `artyfact submit` again (the CLI has no rebase command). `?candidates=a,b` (global) preselects candidates for composition; the Map's "overlap · N" chip links there. Empty: "Nothing is waiting on you." "Waiting for you" is defined once: one decision per open realization, an app candidate submitted, evaluated or selected (stale included) or a Genome amendment awaiting an admin; the promotion row is where a candidate is decided, not a second item. The queue heading, the rail count (`useReviewCount`), the Overview "N waiting for review" line and the Work card's "N await review" count it from the same queries (`useReviewQueue`), and the worker reports the same set as `SystemSummary.realizationCounts.awaitingReview` for Home. The Inspector's "Open in Review" / "in N candidates · overlap" uses the same queries. With `?candidates=` and no row selected, the right pane lists the selection with its Evolution and a "Promote <Evolution>" link when all belong to one Evolution. Works under `/things/:thingId/review`.

## C.7a Home
`/` is outside the System layout: its own header (wordmark, fixture pill and Retry, admin token, "Go to… ⌘K"), `h1 Systems`, a "Needs you" ledger and one card per System from `GET /api/systems`. Everything is computed client-side from that response.

**Needs you.** One row per System with something pending, each a link: "<System> · N await your review" (the server's `awaitingReview`, the rail's number) to that System's head Review, "<System> · deployed, behind" and "<System> · deploy failed" to its Deployments. Row text is attention-toned (danger for a failed deploy). With nothing pending the section is one quiet line, "Nothing is waiting on you." It is plain text, so reduced motion and effects off read identically.

**Card.** System name, id and Phase; one headline sentence by precedence attention > evolving > not built > quiet ("3 await your review", "2 realizations evolving", "not built", "quiet"); one deploy line with the latest build folded in ("deployed · build passed", "deployed, behind", "× deploy failed", "deploying", "not deployed, unknown"); head sha and updated time. Success colour appears only when the build passed. Beside the card, "Describe a change" and, when something awaits, "Review". `observed` is not shown on the card.

**Order.** Cards sort by attention, then evolving, then most recently updated. `cardSummary()` in `views/home/signifiers.ts` produces the headline, tone, deploy line and review link; `needsYou()` produces the ledger rows.

**Go to… ⌘K.** Opens a Home-scoped palette over Systems and shared Parts (Home has no System model, so it does not reuse the System palette's index). An empty API shows an empty state with the `artyfact init` hint; an unreachable API falls back to the bundled fixture.

## C.7b Code
Genome and App tabs, a revision picker, a file tree and a CodeMirror pane. Editing is on head only. Edits are a local draft; Commit… opens a sheet (message, why, Evolution or a new one, name, admin token). The commit starts an editor realization and goes to the fork over Git, then lands on Work as a candidate. A Genome commit becomes `awaiting-admin`. The Inspector's "Open in Code" links the node's source document.

## C.7c Compare
`compare?from=&to=&level=system|genome|files&path=`. System: commit, Genome commit, manifest, template and hook versions. Genome: the semantic delta. Files: changed App and Genome files with a line diff (`data-op="add|del"` rows) for the selected path.

## C.11 Tests
vitest jsdom: model index (`screen.people` children, `entity.ContactRecord` storedIn), status (not-run ≠ pass), useSelection, useMapGraph, useJourneyGraph (J.connect: failure edges, 3 lanes), PromotionPanel disabled/stale. Playwright per route with axe: overview P1 + three meters; map deep link breadcrumbs + grey badges; journeys J.contacts failure edge + inspector; theory T1–T5; work evolution.1 Start work → packet; evaluations/changelog empty states never green.
Three Playwright modes: fixture (default, port 1338, `/api` 404s), fake (`ARTYFACT_E2E_FAKE=1`, port 1339, `FAKE_ARTIFACTS=1` and `ADMIN_TOKEN=test`, specs tagged `@fake`, run one at a time against one in-memory platform) and live (`ARTYFACT_E2E_LIVE=1`, `@live`). The fake specs drive five use cases through the UI: Home, describe a change (Evolution, packet, editor commit, build unknown until a reported preview, health assay), edit and realize (Inspector to Code, commit, accept, Changelog, Home), Compare, and runtime events on Deployments. A second fake server (port 1340, `FAKE_SEED=artyfact`) serves the self-model specs: Artyfact's own Genome on Home, every view without console errors, and an intent under the platform Thing. Further specs cover describing a change by intent (message, routed path, op toggle, accept, candidate, Evolution, packet scope from node `files`), Review (queue rows by kind, the rail's "Review, n waiting", a candidate review, the promotion desk's gates summary and disabled reasons, reject and accept amendments, a candidate turning stale behind the new head) and a sweep of every view on Peopling. Each visited page is checked with axe and for green that is not a pass. `e2e/iteration2.live.spec.ts` repeats the loop against a deployment when `ARTYFACT_ADMIN_TOKEN` is set (`ARTYFACT_CI=1` also waits for a CI build).


## Parts and System entry (accepted contract)

Home has distinct Systems and reusable Parts sections. System-private Parts stay in their System. The atlas opens every System at the Map environment, superseding automatic entry into its sole Thing. Explicit Thing workspaces retain the System breadcrumb and overview, Thing-scoped side rail (no page-level "Thing views" nav), Things switcher and stable direct links when more Things are added. The browser inspects pinned Parts, provenance, source and realized artifacts, and associated Phenome evidence. Authoring remains in CLI/agents.

Public `/`, `/model`, and `/connect-agent` explain ontology import or agent authoring, source mapping, Genome-only Evolution review, Realization Tasks and integrated implementation review, followed by base deployments/metrics/flags and optional outcomes. They preserve Genome-first Things, optional Parts and source versus realized output without presenting Genome/Proteome/Phenome as sequential build stages. Keep Bring your agent primary and preserve prerendered/no-JS content, accessibility and reduced motion. Document only shipped commands. See [GRREAT](../grreat/roadmap.md) for acceptance and progress.
