# Appendix C — UI design (apps/platform/src)

## C.0 Foundations
react-router 7 data mode; routes `/` (Home), `/s/:systemId/r/:rev/{overview,map,journeys,theory,code,work,review,evaluations,changelog,compare,phenome}`, each also under `…/things/:thingId/` (`/s/:systemId` opens the sole Thing's workspace when the System has one Thing, else head's overview; `…/history` redirects to `…/changelog` and `…/work?panel=promote` to `…/review?panel=promote`, both keeping every param and the hash); global params `focus`, `layer`, `candidates` preserved by nav links; view-specific `journey`, `step`, `evolution`, `realization`, `panel`, `evaluation`, `commit`, `repo`, `path`, `from`, `to`, `level`, `deployment`, `build`. The fixture fallback applies only when the API is unreachable; a reachable, empty API shows Home's empty state. TanStack Query 5 for all API calls (poll `/work` 5 s or SSE). `src/api/client.ts`: getModel, getEvolutions, getEvaluations, getHistory, getPacket, startWork, submit, promote; fixture fallback. `src/model/`: `useModel()` {model, byId, children, parent, crossLinks, criteriaFor, rollup}, `useSelection()` {focusId, setFocus(id,{view?}), layer, setLayer, candidates, setCandidates}, `status.ts` verdictOf/rollup (only pass → success colour). `NodeChip` kind→glyph for all kinds.

## C.1 Shell
TopBar: Wordmark (Georgia, links to Home), SystemRevisionSelector (+ state pill canonical | candidate | deployed, options from `GET …/revisions`), PhaseBadge, ⌘K CommandPalette (cmdk over byId). The layer switch (label "Overlay") lives in the Map header. SideNav: Overview, then one group per layer, Private Parts last. Each group is headed by the layer name (its accessible label) with the layer's question beneath in quiet sentence case (its accessible description): Genome, "What should it be" (Map, Journeys, Theory, Code); Proteome, "What is being made" (Work, Review, Evaluations, Changelog); Phenome, "What does it do" (Deployments). The Overview meters carry the same three questions (`LAYER_QUESTIONS` in `model/kinds.ts`). Review shows a count after its label when decisions wait (attention tone, hidden at zero, link named "Review, n waiting"). Compare is not on the rail; it opens from a Changelog row's "Compare with parent" and `g x`. Inside a Thing workspace the rail links resolve to `/things/:thingId/<view>`; there is no separate Thing workspace link. Under 640px the rail collapses to glyphs and keeps the three layer heads visible. Go-to keys: `g o m j t c w r e l x d` (`g h` still opens the Changelog). Main Outlet. InspectorDrawer right 380px resizable, open when focus set; Esc closes; `[`/`]` siblings; `g m`/`g w` shortcuts. Grid `auto 1fr auto`.

## C.2 Map
Files `MapView, useMapGraph, layout/elk.ts, nodes/{SubjectNode,ExternalNode,BoundaryNode,GroupNode}, edges/{CrossLinkEdge}, HierarchyTree, Breadcrumbs, MapFilters, overlays/{PhenomeBadge,ProteomeBadge,CandidateHalo}`. Semantic zoom: focus + children + cross-links among them + touching Externals; double-click child = new focus; breadcrumb/Backspace out. elk layered RIGHT, `hierarchyHandling: INCLUDE_CHILDREN`, orthogonal edges, Externals partition 0 / internals 1, run in Web Worker, memoised per (focus, filters). Containment = nesting, not edges. Edge data `{type: serves|invokes|governs|reads|writes|storedIn|dependsOn|interactsWith, certainty: declared|assumed|proposed}` → solid/dashed/dotted; label chip; hover fan-out. Overlays: Genome plain; Proteome realization-count + apricot ring; Phenome 5 counters (pass green, fail danger, rest subtle); Candidates bracket halo, double bracket + "overlap" chip on shared nodes. HierarchyTree virtualised with keyboard; Breadcrumbs; filters kinds/link types/Externals/findings-only.

## C.3 Journeys (React Flow + elk, not Mermaid)
`JourneysView` (catalog left + canvas), `useJourneyGraph`, nodes Action/System/External/Wait/Decision/Terminal, legend. Lanes actor|system|external as elk partitions with translucent bands; failure/cancel edges dashed danger; branch labels; segments as tabs; provisional steps dotted with "?"; step click sets `?step=` and opens Inspector with jump links ("Open screen.people in Map").

## C.4 Theory
5-column CSS grid Purpose → Beneficiaries → Activities → Outputs → Outcomes (T1–T5); SVG bezier links from DOM rects; inspector shows mechanism/assumptions/indicator/method/horizon/observations; GapsSummary from findings `theory.*`; banner "hypotheses, not a validated causal model".

## C.5 Overview
PurposeCard; ThreeStatesRow (Model readiness · Implementation conformance · Outcome progress — never summed); ActiveEvolutionsCard (with "N waiting for review" → Review); BlockersList (→ rule id, facts, next action); PhaseCard; DeployCard; timestamps; literal "unknown".

## C.6 Work
EvolutionBoard columns by state; EvolutionCard scope chips, "≈ overlap" when any of its candidates conflicts and "N await review" (attention) when candidates or amendments wait; RealizationRow (agent, role, local/hosted, status, fork + short sha, last checkpoint or "unknown", changed subjects, ConflictChips typed, inline "Review" toggle, "Open in Review"); StartWorkPanel → PacketViewer (markdown, copy, CLI line, token countdown); inline CandidateReview tabs Semantic delta / Files / Evaluations / Amendment, "select for composition" → `?candidates=`. Promote is a link to Review (`/review?evolution=E&panel=promote`); `/work?panel=promote` redirects there.

## C.6b Review
`/review` (`views/review/`), the operator's inbox and promotion desk, two panes. Left, the decision queue, grouped by Evolution, one row per pending decision: `candidate` (submitted/evaluated, not promoted or rejected), `stale` (its base is behind head, dashed attention), `amendment` (Genome realization `awaiting-admin`), `promotion` (an Evolution with an evaluated candidate on the current head). A row shows the kind word, agent and role, candidate id, ConflictChips (one per kind, with the count) and "base = head" (neutral) or "behind by N" (attention). Right, the selected row: CandidateReview (`?evolution=&realization=`, its Amendment tab carries Accept with interpretation / Reject with reason) or PromotionPanel (`?panel=promote&evolution=`) with the gates summary "4 pass · 1 unknown" (success tone only when every required gate passes) and, on a 409 stale-base, the agent's recovery line: rebase the fork on the new head and `artyfact submit` again (the CLI has no rebase command). `?candidates=a,b` (global) preselects candidates for composition; the Map's "overlap · N" chip links there. Empty: "Nothing is waiting on you." The rail count (`useReviewCount`), the Work card signals, the Overview "N waiting for review" line and the Inspector's "Open in Review" / "in N candidates · overlap" derive from the same queries (`useReviewQueue`). Works under `/things/:thingId/review`.

## C.6a Describe a change by intent
`?panel=intent` on Work (`views/work/intent/`): a message, optionally anchored on a node, becomes a Proposal (routed path, ops with an include toggle each, questions with inline replies). Accept selected creates the Evolution, realization and candidate, and opens it on Work. While the panel is open it replaces the Evolution board and detail; its head shows the anchor as a node chip with "Clear anchor", and "Back to board" closes it and keeps the other params. "Describe a change" is the one label at every entry (Work header, Home card, Inspector, Code file pane) and the Work header's one primary action; "+ Evolution" is a secondary text button. The UI is driven by template view hints, not by node kind (`docs/design/ontology.md`).

## C.7 Evaluations + Changelog
Evaluations: filterable table → expand Question/Method/Raw observations/Interpretation/Limitations/Provenance; `?criterion=` filters.
Changelog: one dense row per System commit (id, time, who and policy, Evolutions, rationale, node/file/criteria summary, build and deployment chips, fake-provider label). A row expands to the semantic delta, changed app files (each links to Code at that commit), criteria before/after, builds and the deployment, and "Compare with parent". Genome-only commits change nodes and no app file.

## C.7a Home
`/` is outside the System layout: its own header (wordmark, fixture pill and Retry), `h1 Systems` and one card per System from `GET /api/systems`. A card shows phase and the server's signifier chips (evolving, pending realization, awaiting review, not built, deployed or behind, observed, unrealized), the latest build and the deploy state; success colour only for a passed build. An empty API shows an empty state with the `artyfact init` hint; an unreachable API falls back to the bundled fixture.

## C.7b Code
Genome and App tabs, a revision picker, a file tree and a CodeMirror pane. Editing is on head only. Edits are a local draft; Commit… opens a sheet (message, why, Evolution or a new one, name, admin token). The commit starts an editor realization and goes to the fork over Git, then lands on Work as a candidate. A Genome commit becomes `awaiting-admin`. The Inspector's "Open in Code" links the node's source document.

## C.7c Compare
`compare?from=&to=&level=system|genome|files&path=`. System: commit, Genome commit, manifest, template and hook versions. Genome: the semantic delta. Files: changed App and Genome files with a line diff (`data-op="add|del"` rows) for the selected path.

## C.7d Deployments
`/phenome`, labelled Deployments: builds with steps, deployments (each links to its System commit and its events), runtime events grouped by version key (realized output ID when known, else `buildId` or `commit`) with the System commit, and the outcome criteria. `?deployment=` and `?build=` filter.

## C.8 Inspector
Header (NodeChip, id copy, Open in Map/Journeys/Theory/Work; "Open in Review" instead of Work, with "in N candidates · overlap", when a candidate in `?candidates=` or waiting in Review touches the node) + tabs What (kind body registry `bodies/index.ts`, each agent appends own file) · Why (sources, GD→S→C chain, Purpose/Theory, commitment bundles) · Dependencies (links grouped by type) · Changes · Rules & claims (owner / subject / target on three lines) · Evidence.

## C.9 Theme
`src/theme/{tokens.css, whimsy.css (data-attribute block rewritten to :root), utilities.css, reactflow.css}`; vanilla CSS + CSS Modules. Utilities: `.u-brackets` (4 L-corners 4px outside, opacity/scale 180 ms, reduced-motion safe; `--on` persistent), `.u-segments` (tapered 2px lines above/below active tab via mask-image), `.u-marker` (apricot /0.22 highlight). Verdict tokens map pass→success, fail→danger, unknown/stale/not-run→text-subtle (stale dashed). React Flow overrides: surface-secondary nodes, border-subtle, radius-md, no shadow, no pills.

## C.10 Ownership
A shell/api/model/theme/components/inspector skeleton → B map + `src/graph/*` → C journeys + theory → D work/evaluations/history/overview. A lands the contract commit (hook signatures, NodeChip props, route stubs, theme, client with fixture fallback) first.

## C.11 Tests
vitest jsdom: model index (`screen.people` children, `entity.ContactRecord` storedIn), status (not-run ≠ pass), useSelection, useMapGraph, useJourneyGraph (J.connect: failure edges, 3 lanes), PromotionPanel disabled/stale. Playwright per route with axe: overview P1 + three meters; map deep link breadcrumbs + grey badges; journeys J.contacts failure edge + inspector; theory T1–T5; work evolution.1 Start work → packet; evaluations/changelog empty states never green.
Three Playwright modes: fixture (default, port 1338, `/api` 404s), fake (`ARTYFACT_E2E_FAKE=1`, port 1339, `FAKE_ARTIFACTS=1` and `ADMIN_TOKEN=test`, specs tagged `@fake`, run one at a time against one in-memory platform) and live (`ARTYFACT_E2E_LIVE=1`, `@live`). The fake specs drive five use cases through the UI: Home, describe a change (Evolution, packet, editor commit, build unknown until a reported preview, health assay), edit and realize (Inspector to Code, commit, accept, Changelog, Home), Compare, and runtime events on Deployments. A second fake server (port 1340, `FAKE_SEED=artyfact`) serves the self-model specs: Artyfact's own Genome on Home, every view without console errors, and an intent under the platform Thing. Further specs cover describing a change by intent (message, routed path, op toggle, accept, candidate, Evolution, packet scope from node `files`) and a sweep of every view on Keep in Touch. Each visited page is checked with axe and for green that is not a pass. `e2e/iteration2.live.spec.ts` repeats the loop against a deployment when `ARTYFACT_ADMIN_TOKEN` is set (`ARTYFACT_CI=1` also waits for a CI build).


## Parts and single-Thing entry (accepted contract)

Home has distinct Systems and reusable Parts sections. System-private Parts stay in their System. Opening a one-Thing System enters the full Thing workspace with a System breadcrumb and explicit overview; the side rail serves the Thing scope (there is no page-level "Thing views" nav), and the page keeps the breadcrumb, the Things switcher and its cards; direct Thing links remain stable when more Things are added. The browser inspects pinned Parts, provenance, source and realized artifacts, and associated Phenome evidence. Authoring remains in CLI/agents.

Public `/`, `/model`, and `/connect-agent` explain Genome-first Things, optional Parts, and source versus realized output without presenting Genome/Proteome/Phenome as sequential build stages. Keep Bring your agent primary and preserve prerendered/no-JS content, accessibility and reduced motion. Document only shipped commands. See [GRREAT](../grreat/roadmap.md) for acceptance and progress.
