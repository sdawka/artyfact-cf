# Appendix C — UI design (apps/platform/src)

## C.0 Foundations
react-router data mode; routes `/` (Home), `/start`, `/parts/:partId/:version`, `/style`, `*` (NotFound), `/s/:systemId/r/:rev/parts` (Private Parts), `/s/:systemId/r/:rev/{overview,map,journeys,theory,code,work,review,evaluations,changelog,compare,phenome}`, each also under `…/things/:thingId/` (atlas entry: `/s/:systemId` opens head's Map environment for every System; explicit Thing routes remain valid; `…/history` redirects to `…/changelog` and `…/work?panel=promote` to `…/review?panel=promote`, both keeping every param and the hash); global params `focus`, `layer`, `candidates` preserved by nav links; view-specific `journey`, `step`, `evolution`, `realization`, `panel`, `evaluation`, `commit`, `repo`, `path`, `from`, `to`, `level`, `deployment`, `build`. The fixture fallback applies only when the API is unreachable; a reachable, empty API shows Home's empty state. TanStack Query 5 for all API calls (poll `/work` 5 s or SSE). `src/api/client.ts`: getModel, getEvolutions, getEvaluations, getHistory, getPacket, startWork, submit, promote; fixture fallback. `src/model/`: `useModel()` {model, byId, children, parent, crossLinks, criteriaFor, rollup}, `useSelection()` {focusId, setFocus(id,{view?}), layer, setLayer, candidates, setCandidates}, `status.ts` verdictOf/rollup (only pass → success colour). `NodeChip` kind→glyph for all kinds.

Shared application controls live in `components/ui`: Radix Select/Popover/Dialog/Sheet/Menu/Tabs/ToggleGroup with Artyfact CSS Modules, native Input/Textarea/Checkbox and composable Button/IconButton. Standard controls are 44px; feedback is 100ms, overlays 180ms and drawers 300ms. Portaled surfaces carry Effects preference and reduced motion suppresses transitions. Select preserves domain form values, explicit empty All options, placeholders, groups and unknown values. `/style` shows these real shared states.

**Cross-page rules** (`src/theme/README.md` has the token detail).

| Topic | Rule |
|---|---|
| Apricot | The operator's colour: where you are (current rail row, selected row's rule), what you can do (the one primary) and what waits on you (`--color-attention` counts and "await your review" rows). Links are text with a 1px apricot underline; ids, logs, breadcrumbs and counts that do not wait are not apricot. |
| Glow | Only for selection and status, through the effect tokens and always beside the outline or rule that carries the meaning. No resting or hover glow on rail, cards, tiles, menus or buttons; no apricot inset rails. Only `pass` glows or reads green. |
| Selection | One rule: a 2px apricot left rule plus one surface step (`.u-selected` / `.u-selectable` on `aria-current`, `aria-selected`, `aria-pressed`). Hover is the surface step; the focus ring shows on `:focus-visible` only, including script-focused headings. `aria-pressed` is styled once in `ui.module.css`. |
| Primaries | One per view. An open Panel or a selection with its own primary turns the header's primary secondary. A disabled primary uses the disabled token and shows its first reason inline (`Button reason`), the rest folded ("N more reasons"). |
| Admin token | The header is the one source; writes without it are disabled with "Set the admin token in the header." Exception (decision g): Private Parts keeps its own "Admin token or realization secret" field, kept in memory only. Still to remove: Deployments' Operations gate keeps its own token field, and the promotion, amendment and import Decision forms show one while the header token is unset. |
| Markers | `.u-marker` only on the one next-step link of an empty state or ledger row, at most two per region; never on ids, logs, breadcrumbs or list items. |
| Empty states | Say what to do next with one action, once per region (once for a wholly empty page); a load failure is an error state with its cause and "Try again", never an empty one. The literal "unknown" is for unknown values only. |
| Metadata | One bordered chip per row (its state); other facts are `MetaLine` or `StatusText`. Ids, shas and paths in the code face, short in rows and full in `title` and Copy; times relative with ISO in `title`. |
| Horizontal scroll | No view scrolls sideways at any width down to 320px; only tables, code and canvases scroll inside their own container. |
| Effects budget | The Shell's ambient field plus at most one `SurfaceField` per view. |
| Vocabulary | "Shared Parts" and "Private Parts"; "Describe a change" everywhere; "Open in Review" for every go-decide link; "Back to {region}"; "Add to promotion" (URL `?candidates=` and Genome ids keep the old composition naming). |

**Fonts** (decision a): Alegreya for display (wordmark, page h1, the System name; one display element per view), Atkinson Hyperlegible Next for UI and body, Atkinson Hyperlegible Mono for ids, shas, commands and paths. All OFL, self-hosted as the same versioned files in both apps, UI face preloaded, metric-matched fallbacks.

**Page grammar.** Every view opens with one `PageHeader`: an optional context line (System / Thing / View inside a Thing, Environment / … on a Map scope; plain links, current item as text), the h1 (`id="view-title"`, `tabIndex=-1`), one purpose sentence (≤70ch), up to three status chips about the whole page, and actions with at most one primary (on mobile they wrap under the purpose, primary first). Archetypes:
- *Dashboard* (Home, Overview): answers "what needs me?" first (a Needs you ledger of whole-row links), then state as registers (`RowList` + `Row`, aligned columns).
- *Workbench* (Review, Work, Code, Changelog, Private Parts): `ListDetail`, list 20–24rem with its own scroll, detail fills the rest. Nothing selected opens the first item that needs you (never "Select…"). Below 900px it is one pane at a time with "Back to {list}".
- *Canvas* (Map, Journeys): compact header; panels overlay the canvas and never resize it; the gutter applies.
- *Reading and form* (Theory, Part, Start): one 68ch column; numbered `Steps` only where the order is real (Start).
A `Panel` replaces the region it is about, with its own h2, primary and "Back to {region}"; focus moves to its h2 and returns to the opener on close. Primitives: `PageHeader`, `Section`, `Panel`, `ListDetail`, `RowList`/`Row`, `MetaLine`, `StatusText`, `Count`, `Kbd` (platform aware, Ctrl K off Mac), `Steps`, `Button reason`, `EmptyState kind=empty|error`.

## C.1 Shell
TopBar, one row: Wordmark (Alegreya, to Home), the System and Revision selects with a state pill only for candidate or deployed (no "canonical" pill at head), a Workspace status group (Phase, "⊘ Fixture data" with Retry API, the hosted-demo pill, "fake provider"), then "Admin token" (popover; "Admin" with a set status once saved; Save and Forget; session only), "Effects: on/off" (`aria-pressed`), "Go to…" with the platform-aware key hint, and a More menu. Below 1280px Retry API and Effects move into More; compact screens add a Menu button (the rail as a sheet) and move "Admin token…", Phase and the provider into More. The layer switch (label "Overlay") lives in the Map toolbar. There is no Shell breadcrumb: scope lives in each PageHeader's context line.

SideNav (labelled Views): inside a Thing a scope row "In {Thing}" with "Leave" first; then Map and Overview, one group per layer headed by the layer name (its accessible label) with the layer's question beneath (its accessible description): Genome, "What should it be" (Journeys, Theory, Code; Journeys and Theory only when the templates declare them); Proteome, "What is being made" (Work, Review, Evaluations, Changelog); Phenome, "What does it do" (Deployments); then Private Parts. The Overview meters carry the same three questions (`LAYER_QUESTIONS` in `model/kinds.ts`). Review shows a count when decisions wait (`useReviewQueue`, "Review, n waiting"); Work shows tasks ready for an agent (`planCounts.awaitingAgent`, "Work, n ready for an agent"); both attention toned and hidden at zero. The current row carries the selection rule; nothing glows at rest. Compare is not on the rail; it opens from a Changelog row's "Compare with parent", the palette and `g x`. Inside a Thing the rail links resolve to `/things/:thingId/<view>`. Below 1024px the rail is a labelled modal Menu sheet; desktop keeps a 256px rail.

Command palette, titled "Go to" (Mod+K toggles): groups Views (rail order then Compare, each with its go key, Review with its count), Nodes (top 50) and Actions ("Describe a change", anchored to the focused node when there is one; "Admin token…"; "Retry API" with fixture data only; "Effects: turn on/off"), and a key footer (↑ ↓ move, Enter open, Esc close, `[ ]` siblings when a node is focused). Go keys: `g` then within a second `o m j t c w r e l x d` (`g h` still opens the Changelog); ignored while typing, with a modifier or while a dialog, menu or listbox is open.

Main Outlet. InspectorDrawer right, 380px default, resizable 280–720px (grip "Resize Inspector", arrows step 16px), bottom sheet below 1024px; other views open it when focus is set, while Map requires explicit Details (`inspect=1`). Esc clears the focus (on the Map it closes Details); `[`/`]` move to the previous/next sibling node. Routes outside the System layout: `/` Home, `/start`, `/parts/:partId/:version`, `/style`, and `*` → NotFound ("Page not found", "Nothing lives at {path}.", primary "Open Home", link "Start a System"). A failed route load shows RouteError ("This System could not be loaded." or "This page could not be loaded.", the cause as an alert, primary "Try again", secondary "Open Home"); a stale chunk after a deploy reads "The app was updated. Reload to continue." with "Reload". Both use Home's header.

## C.2 Map
Map is the primary System entry, followed by the existing specialized views. React Flow provides the viewport; deterministic `atlasLayout` packing replaces Map ELK placement. Environment shows the System and all declared externals, including disconnected actors, without invented roles. Entered scopes show their immediate real containment children and direct one-hop outside context; template view hints never skip containment. Outside scope and outside System remain distinct.

Tiles form a rectangular mosaic without gutters, using thin shared dividers and content-based S/M/L budgets for name, kind, short purpose and bounded child previews. Geometry is independent of selection, relationship visibility, Details and layer overlays. Genome, Proteome and Phenome remain parallel overlays on that same layout; existing evidence and candidate signals retain their meanings. System tiles and entered scope boundaries use a stronger teal treatment while preserving readable labels and purpose text. Selection shows by weight, text-primary and the selection glow beside its outline; hover draws the boundary connections; rest stays quiet, with no resting glow and no inset accent rails. Direction follows actual geometry, accents do not shift layout, and keyboard focus/candidate marks remain distinct. Relation emphasis never implies a successful verdict. Details is the primary explicit inspection control.

Header: compact PageHeader (h1 Map, scope path Environment / … as context, primary "Enter {System}" at Environment). Toolbar: Up, Tree, Filters and "Outside (n)" (a menu of "Show {name} on map", only when n > 0), the Overlay tabs, and a key hint (Drag pan, Enter open, D details, Backspace up). Filters is a side panel titled Connections: All connections, Show Externals, Findings only, then Layers, Kinds and Link types groups with "n hidden" and Reset. A map key (declared, assumed, proposed, outside System, candidate touches) sits bottom-left. Selecting docks the tile's name with Details (primary), "Enter {name}" and "Connections (n)"; Connections rows read "from → to" with relation, label and certainty and "Show {end} on map" for both ends (empty: "No connections cross this boundary."). A container tile offers "Open, n inside"; an empty scope reads "Nothing inside {name} yet." with Describe a change. Two or more candidates on a tile show "Overlap, n candidates", linking to Review with `?candidates=`; halos come only from `?candidates=` (there is no Candidates toggle).

Click selects and reveals boundary-crossing relationships; Details explicitly opens the Inspector. Enter or double-click opens only nonempty containers; leaves remain inspectable. Grouped lines retain every normalized original endpoint, relationship, label, certainty and count, with actual endpoint paths and "Show {name} on map" actions exposed in the Connections panel and the Inspector. Offscreen selected endpoints have indicators. Tree and filters are on demand; mobile uses compact context and a bottom Inspector.

Map URLs use `scope=environment|containerId`, `focus` for selection, and `inspect=1` for Details. Valid explicit scope wins; legacy focus and Thing routes remain supported. Scope changes push browser history; selection and Details replace it. Selecting closes Details without changing scope. Cameras restore per System/revision/scope. Drag, ordinary scroll and touch pan; pinch or modified scroll may enter/leave depth only past a threshold, once per gesture, never entering an empty container or leaving environment. Explicit Up/Enter and keyboard paths remain available; reduced motion makes transitions immediate. `useAtlasReveal` provides a stable 180ms opacity reveal only when scope changes, with no initial autoplay or replay on selection or layer changes. Enter/Up/Show-on-map camera transitions preserve node anchors and saved viewport returns; interrupted or stale requests are cancelled. Overlay openings use the shared 180ms token. Interruptions, unmount and preference changes cancel active motion. Effects off or reduced motion disables these transitions; geometry and cameras stay unchanged.

The released atlas baseline and current polish validation are distinguished in [GRREAT](../grreat/execution.md); hosted checks and release evidence follow integrated validation.

## C.6 Work
New work follows the [lifecycle](lifecycle.md): Genome-only Evolutions and separate Realization plans pinned to accepted Genome revisions. Work exposes Tasks, scope interference, dependencies, attempts and integration. Task selection and the combined implementation review live in Review. Older Evolution-owned attempts remain readable as legacy history. `/start` previews native ontology packages and preserves invalid conversion output for correction before exact-hash acceptance. Its local handoff materializes reviewed files with `ontology bootstrap --prepare-only`, installs instructions in that project, and supplies the platform origin and per-command credential placeholders. Genome-only Systems are valid; implementation starts after source preparation, reviewed import and a draft using actual source-bound nodes.

Work is a workbench (decision c): PageHeader "Work" with status counts as links ("N tasks await an agent", "N await review"), primary "Describe a change" (secondary while a panel or the selection offers its own primary) and secondary PlusIcon "Evolution" (`?panel=new`). One list pane: Plans first, then Evolutions in state groups (`EvolutionGroups`: Proposed, Genome approved, Actionable, Realizing, Evaluated, Promoted, Rejected, Withdrawn, then a collapsed read-only "Legacy (n)"); groups with attention or the selection open, terminal groups start closed, empty groups are one line. A row shows checks ("k/n pass"), "≈ overlap" and "N await review" (attention) and "Open in Review". With nothing selected at ≥900px the first plan with a task awaiting an agent opens, else the first Evolution that needs review or overlaps. Below 900px one pane with "Back to Work". No board, no columns, no sideways scroll.

Evolution detail: h2 with state, "Start work" primary while actionable or realizing (else a disabled secondary with its reason) and "Promote in Review" (`/review?evolution=E&panel=promote`, keeping `?candidates=`; `/work?panel=promote` and `/work?realization=` redirect to Review). Acceptance criteria, then Attempts: RealizationRow (agent, role, target, status, fork and checkpoint or "unknown", token countdown attention under 30 min, BuildChip, changed subjects, ConflictChips naming the other candidates, "Open in Review"). StartWorkPanel replaces Attempts ("Back to Evolution") → PacketViewer (start command shown once with "Copy command", Task Packet with "Copy packet", token countdown). Candidate review lives only in Review. NewEvolutionPanel ("Back to Work"): Title, Intent, Affected nodes, Acceptance criteria (System defaults or "Choose criteria" with a filter), Risk radios; no Kind select. Every form reads the header token.

**Plan** (`views/work/plan/`; `?panel=plan` for the draft, `?plan=` and `?task=` for the detail). The list and detail read `src/api/lifecycle.ts`, polled (plans emit no SSE events); counts use the live `GET /api/systems/:id`, never the cached systems list. Writes need the admin token and say so.
- *Draft flow.* The draft panel picks accepted Genome Evolutions, optional node ids and a hint, and "Draft tasks" posts to the draft route (backend.md B.9), which saves nothing. It shows provenance, problems and the drafted waves. Rename, merge (same binding only, dependents repoint), split by write nodes (dependents wait on both halves) and remove edit the draft in the browser; the waves line then says they are recomputed on create. `draftErrors` catches what create would refuse (duplicate ids, unknown dependencies, cycles, no title, no write node). "Create plan" posts `{...draft.request, title, tasks}` unchanged to create. There is no plan PUT, so a created plan is edited by drafting again.
- *Waves.* Waves stack vertically, one region per `analysis.waves` entry, "Wave n · k tasks" (1-based). `TaskCard`: status chip (`pending ○ claimed ◔ working ◑ submitted ◕ selected ◉ completed ●`; blocked is a pending task with a dependency that has no selected candidate, shown with "waits on …"), up to four write-node chips, binding and footprint line, depends-on, conflict chips (dependency, source, ontology, unknown; each names the other task, none danger-toned) and "awaits an agent".
- *Commands.* Each wave lists, per task an agent can take now, the claim line and an agent subshell, with Copy and Hide each: `ARTYFACT_ADMIN_TOKEN="$ADMIN_TOKEN" npx artyfact task claim <plan> <task> --system <sys> --dir ./work/<task>` and `( cd ./work/<task> && env -u ARTYFACT_ADMIN_TOKEN claude -p '<prompt>' )`. A lapsed lease shows `resume`; a task a conflicting live attempt blocks, or whose id fails the CLI's id rule, shows its reason instead. Every id is shell-quoted. "Copy all" runs each still-shown claim from the shell's own directory and, only when it succeeds, its agent subshell in the background (`claim && { agent & }`), then one `wait`, so a wave's agents run side by side and a failed claim never starts its agent. Two task ids that differ only in case get no command (one `./work` directory on macOS). The plan detail's primary is "Copy all, wave N" for the first wave with commands (later waves keep a secondary "Copy all"); it is disabled with "Every command is hidden." once everything is hidden. The SPA never handles credentials: the claim reads the token from `ADMIN_TOKEN`, a shell variable the person sets without exporting it (the hint says so), and the line that starts the agent unsets it.
- *Task detail.* Why the task is in its wave, its command, write and read nodes, the footprint (globs, files written, unmatched files, read scope), steps, checks with `VerdictBadge`, depends-on, attempts, and the select form for a submitted candidate. "Integrate selected Task results" is disabled with its reason until every task is selected; once integrated, `PlanReview` shows the combined implementation review and per-binding changes before promote. A 409 `replan-required` says to create a new plan.
- Fixture data shows the list read-only with every write disabled.

## C.6a Describe a change by intent
`?panel=intent` on Work (`views/work/intent/`): a message, optionally anchored on a node, becomes a Proposal (routed path, the agreement tree over its ops, questions with inline replies). The proposal already links to a durable Genome Evolution. Accepting commits the agreed Genome change at once; implementation starts separately in a Realization plan. While the panel is open it replaces the list and detail; its head shows the anchor ("Starting from …" with "Clear anchor"), "Start over" once a proposal exists, and "Back to Work" closes it and keeps the other params. The form is "What should change?" with "Propose changes"; questions take "Reply". "Describe a change" is the one label at every entry (Work, Overview and Thing headers, Home rows, Inspector, Code file pane, palette) and the Work header's primary; "Evolution" with a plus icon is a secondary. An op's diff opens under "Show before and after". The UI is driven by template view hints, not by node kind (`docs/design/ontology.md`).

**Agreement tree** (`intent/agreement/`, `AgreementTree`): `Proposal.plan` as rows rooted at Things, each with the kind glyph, title, counts ("3 add · 2 update · 1 remove" over its subtree), the rollup word (agreed, rejected, deferred, mixed, undecided) and Agree / Reject / Defer toggles (`aria-pressed`, named "Agree <title>"). An open node shows its own ops' diffs; no per-op checkboxes. Children inherit a node's decision; deciding a node clears its descendants' decisions, and a child decided afterwards overrides it (the parent shows "mixed"). Backspace or a second click clears a node's own decision. A node with an `error` problem cannot be agreed; an agreed op that needs a rejected or deferred one is left out and its node says "needs <title>". Decisions persist through `PUT …/intents/:pid/decisions` (optimistic, rolled back on refusal; ontology.md §5); a proposal without a stored plan gets one from the model index (`planFromOps`) and keeps decisions in the view. Rule styles, never green: agree solid apricot, reject dashed with secondary text, defer dotted with a "deferred" chip, mixed at half strength. All open when at most five nodes own ops, else only the Things. Keyboard: one tab stop with roving focus; ↑↓ move, → opens or enters, ← closes or goes to the parent, Home/End, Enter/Space open and close, `a` `r` `d` decide, Backspace clears; a hint line under the tree says so. Variant `genome` (import and amendment review) has no Defer. Fixture: every decision disabled, the tree still navigable.

**Accept agreed** (the panel's primary, in a sticky footer) sends the agreed, unblocked ops; it is disabled with a reason while any node is undecided or nothing is agreed. The summary reads "11 of 14 changes agreed · 1 deferred · 2 rejected". It commits exactly the agreed changes to the Genome. With deferred nodes the platform moves their ops to a new proposal with its own Evolution and the panel stays open: "Accepted 11 changes into <Evolution> and committed them to the Genome. 3 deferred changes wait in a new proposal." with "Continue with deferred" (opens that proposal) and "Open the accepted change"; otherwise the accepted Evolution is selected.

## C.6b Review

Review is the unified decision desk (`views/review/`): PageHeader "Review", purpose "Decisions that need a person: imports, Task results, candidates, amendments and promotions.", no header actions. `ListDetail`: left the queue, h2 "Waiting on you N" (attention), grouped by Evolution or plan (group heads link to it in Work), "Import" first; right the open decision, whose own header carries its primary. With nothing open at ≥900px the first waiting decision opens (history replace, focus stays). j/k move through rows and Enter opens (decision i; hint "j k move · Enter open"). Below 900px it is two screens with "Back to queue". Empty: "Nothing is waiting on you." with "Open Work"; a partial load says "The decision queue could not be fully loaded." rather than claiming nothing waits. A missing target ("No realization X on this System.") offers "Open a decision from the queue." Works under `/things/:thingId/review`, filtered to the Thing with "Show all" (decision f).

**Rows.** Kind glyph and an outcome sentence: ◇ candidate ("Submitted, checks pending" / "Evaluated candidate to review"), ↻ stale ("Built on an earlier head", attention), ✎ amendment ("Genome amendment awaits an admin"), ↑ promotion ("Ready to promote, N candidates evaluated", trailing "Promote"), ⤓ import ("Import · N nodes awaits an admin", "new work waits until it is accepted"), ◎ integrity ("Integrity review: automated {status}, agreement pending" or "Integrity check {state}"; opens `?integrity=` with automated result and human agreement kept apart), ◇ task ("{task}: result awaits selection"), ↑ plan ("Plan awaits promotion"). Meta: agent and role, candidate id, "base = head" (neutral) or "↻ behind by N" / "behind head" (attention), "● in promotion" when in `?candidates=`, compact ConflictChips (one per kind). Within a group: import or amendment, then candidates, then the promotion row. A submitted Task contributes one selection decision (`?plan=&task=`), an integrated plan one promotion decision (`?plan=`); selected Tasks and promoted plans contribute zero. The import row exists while `SystemSummary.importReview` is pending (new Evolutions, realizations, intents and lifecycle work are refused with 409 `import-unreviewed` until then), unless `GET …/import-review` says accepted.

**Details.** CandidateReview (`?evolution=&realization=`): h2 the Evolution title with the verdict summary chip ("✓ 4 pass · ? 1 unknown"; success only when every required gate passes), meta (behind, candidate, agent, state, base, build with Preview), secondaries "Add to promotion" (pressed toggle over `?candidates=`) and "Re-run checks", tabs Semantic delta / Files / Evaluations / Amendment. PromotionPanel (`?panel=promote&evolution=`): h2 "Promote {Evolution}" with gates summary and "Promote" in its header, first reason inline and "N more reasons" folded; Blocking, Candidates, Base and head, Required gates, Advisories, Rationale; a 409 stale base says the head moved and that the agent rebases the fork and runs `artyfact submit` again (there is no rebase command); success links "Open in Changelog" and "Open Deployments". `?candidates=` with nothing open lists them under "Added to promotion" with "Promote {Evolution}" when they share one Evolution; the Map's overlap chip links there. TaskReview (`?plan=&task=`): exact candidate files (line diffs), changed Genome nodes, recorded evaluations and "Select reviewed Task result"; PlanReview: "Combined implementation review" with "Promote reviewed implementation". "Waiting for you" is counted once (`useReviewQueue`) for the queue heading, the rail, Overview's Needs you row and Work's counts; the worker reports the same set to Home.

**Import review** (`?panel=import`, `GenomeReview`): the containment tree with Agree and Reject per node, readiness findings ("Show all N"), unmapped paths with their total, an interpretation field, and "Accept import" (or "Accept import, remove N rejected"). It is two-state, pending then accepted; accepting with rejected nodes removes them in the same step (backend.md B.10), reads "N rejected node(s) were removed from the Genome (System commit abc1234)", links "Open the removal amendment" and lists `warnings` for live Evolutions whose criteria the removal deletes. There is no whole-import reject: reject nodes and accept the rest, or delete the System and import it again. When the review 404s, or the summary says there is none, the detail reads "No import review on this System." / "A pending Genome import appears here." with "Back to queue", and the list's back link is suppressed; other errors offer a retry. **Amendment review** (the Amendment tab): the same agreement tree, read-only once decided, readiness diff, System One signals, then "Accept amendment" with a required interpretation or "Reject amendment" with a required reason.

## C.7 Evaluations + Changelog
Evaluations: purpose "Evidence for each criterion, with method and limits."; filters Candidate / Criterion / Verdict / Execution (URL params) with "k of N results" and "Clear filters"; `?criterion=` reads "Showing evidence for {title}" with Clear. The table groups by candidate when there are two or more; a row expands (`?evaluation=`) to Question/Method/Raw observations/Interpretation/Limitations/Provenance. Kind glyphs are hidden in verdict rows. Empty "No evaluations yet." with "Open Review"; no match "No evaluations match these filters." with "Clear filters".
Changelog: purpose "Every System commit, newest first."; secondary "Evolution" (PlusIcon, `?panel=new`, "Back to Changelog"); an Evolution filter. ## Parts and System entry (accepted contract)

Home has distinct Systems and reusable Parts sections. System-private Parts stay in their System. The atlas opens every System at the Map environment, superseding automatic entry into its sole Thing. Explicit Thing workspaces keep the System link and a Thing select in the PageHeader context line, the Thing-scoped rail with "In {Thing} · Leave", "Related views" links, and stable direct links when more Things are added. Thing-scoped Work, Review and Deployments filter to the Thing with "Show all" (decision f). The browser inspects pinned Parts, provenance, source and realized artifacts, and associated Phenome evidence. Authoring remains in CLI/agents.

Public `/`, `/model`, and `/connect-agent` explain ontology import or agent authoring, source mapping, Genome-only Evolution review, Realization Tasks and integrated implementation review, followed by base deployments/metrics/flags and optional outcomes. They preserve Genome-first Things, optional Parts and source versus realized output without presenting Genome/Proteome/Phenome as sequential build stages. Keep Bring your agent primary and preserve prerendered/no-JS content, accessibility and reduced motion. Document only shipped commands. See [GRREAT](../grreat/roadmap.md) for acceptance and progress.
